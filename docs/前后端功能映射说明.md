# 乐道AI · 前后端功能映射关系说明

> 对应截图：图1 = 用户端「圈子」页（前端功能面）；图2 = 管理后台侧边栏（后端管理面）。
> 本文档逐一梳理前端每个功能的字段定义、请求参数、接口调用方式、数据结构，并对应到后端具体实现位置；最后列出本轮补齐的差异项。

## 0. 总体架构（先读这一段）

```
用户端 index.html + js/app.js ─┐
                              ├─ 共用 js/data.js（Store，localStorage TQ_DB_V1 缓存）
后台 admin.html + js/admin.js ─┤      │
                              │      ├─ 读：启动时 CloudSync.init() 从云端 tq_content 拉取
                              │      └─ 写：Store.save() 防抖 600ms 推送云端（15 个内容域 scope）
                              │
                              └─ 轻量后端 server.js（零依赖 node）：提供强校验 / 计算类 API
                                 路由：POST /api/<handler>，apiHandlers 表分发（server.js:81 起）
```

- **数据模型（云端 tq_content 表，scope 主键 + JSONB data）**：`config / bosses / salons / notices / posts / banners / vipPage / signups / commissions / referrals / coopLeads / distTeam / members / upsells / distApplyList`（js/data.js:17 `CONTENT_SCOPES`）。
- **本机域（不上云）**：`user`（登录态/会员态/顾问态）、`notifs`（站内通知）、`clients`（锁粉演示数据）。
- **路由层**：前端 hash 路由（app.js routes 表 + 参数路由 `circle-detail/:id` 等）；后台无路由，`Admin.go(page)` 切换 `.page` 显示（admin.js:68）。
- **「控制器/服务」的对应物**：用户端 `User.*` 方法（app.js:1344 起）＝业务服务层；后台 `Admin.*` 方法＝管理服务层；server.js `apiHandlers` ＝强校验接口层。

| 9 | 我的动态（待审核/已发布/已下架/已驳回 + 驳回原因） | `p.status ∈ pending/on/off/rejected`、`p.rejectReason` | 无接口，直读 | posts[].status/rejectReason | **原后台无法流转这些状态（缺口②）** → 本轮新增 `Admin.modPost/togglePostPin/editPost/delPost` |
| 10 | 会员/游客门槛（circle-pub 两种拦截页） | `db.user.member`、`db.user.advisorAdded` | 无接口 | user（本机域） | 服务端 `/api/post/check` 二次校验，防绕过 |

## 3. server.js API 清单（强校验层）

| 接口 | 请求参数 | 校验逻辑 | 返回 | 前端调用点 |
|---|---|---|---|---|
| `POST /api/ticket/quote` | salonId/price/mprice/isMember/ticketAdjust/boughtCount/today | ticketCalc：生效窗口/限购/会员价 | finalPrice/remaining/limitOk/hint… | app.js `ticketQuote()`（展示价回填，fromServer 才动作） |
| `POST /api/ticket/confirm` | 同上 + name/phone/qty | 限购校验（含 qty 累计） | ok+finalPrice+orderNo+code，或 {ok:false,reason:'limit'} | app.js `confirmSalonPay()`（金额与凭证号以服务端为准） |
| `POST /api/post/check` **（本轮新增）** | content/cat/images/member/advisorAdded | 分类枚举；会员门槛；顾问门槛；非空；≤2000字；maskSensitive 打码 | ok+打码后 content+flags+msg | app.js `cclPublish()`（服务端优先，失败本地 cclMask 兜底） |
| `POST /api/wx/exchange` | code/from(wxmp\|wxopen) | 未配 AppId → 演示模式；已配 → 微信 oauth2 两步 | openid/nickname/avatar | auth.js 登录链路 |
| `POST /api/video/resolve` | url | 多级302跟随 + gzip/br 解压 + charset 识别 + og:image/JSON 键名兜底 | ok+title+cover | admin.js `grabCover()`（老板封面/沙龙封面复用） |

## 4. 本轮补齐的差异项（缺口 → 实现）

| 缺口 | 前端表现 | 补齐内容 | 改动文件 |
|---|---|---|---|
| ① 后台无圈子动态管理 | posts 的 status/pinned/videoUrl 等字段前端在消费，后台却无任何入口（seed 里 cp_005 永远停在「待审核」） | 新增侧边栏「📝 圈子动态管理」：待审核置顶排序 + 状态筛选 + 通过/驳回(填原因)/下架/重新上架/置顶/编辑(内容+探访视频链接)/删除；数据看板加「待审动态」统计 | admin.html、admin.js |
| ② 审核状态无流转闭环 | 「我的动态」展示 待审核/已发布/已下架/已驳回+原因，但无人操作 | 缺口① 的 modPost 驳回必填原因（rejectReason 落库），用户端实时可见 | admin.js、admin.html |
| ③ 敏感信息打码只有文案没有实现 | 发布页承诺「手机号/微信号/QQ/邮箱自动隐藏」，原代码原样入库 | app.js 新增 `cclMask()`（手机/邮箱/QQ/微信号 4 类正则打码）；cclPublish 改为：服务端 `/api/post/check` 校验并返回打码后文案 → 落库；接口不可达时本地同规则兜底；打码处数以 toast 提示 | server.js、app.js |
| ④ 分类字典两套维护 | 前端 CCL_CATS 与后台各写一份 | 后台新增 CCL_CATS/POST_ST 字典并与前端文案一致（renderPosts 使用） | admin.js |

> 未改动项说明：referrals（引荐单）的消费端在老板工作台（js/workbench.js）与分销中心（js/distro.js），后台订单页通过 signups(kind=refer) 视图呈现，链路已闭环，无需新增。vipPage 为会员落地页文案域（后台暂未提供编辑界面，空值走内置默认），属后续可选项，不在图1/图2 红框范围内。
