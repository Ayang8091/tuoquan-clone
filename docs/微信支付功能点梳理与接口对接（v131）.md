## B. 新增后端能力（server.js）

| 接口 | 请求 | 参数校验 | 行为 | 返回 |
|---|---|---|---|---|
| `POST /api/pay/upload` | `{ kind:'wx'\|'ali', dataUrl }` | 仅 `data:image/(png\|jpeg\|jpg\|webp)`；内容 ≥100B；≤800KB | base64 解码写入 `uploads/payqr-{kind}-{ts}.{ext}`，同一 kind 只保留最近 5 张 | `{ok, url:'/uploads/…', kind, size}` |
| `POST /api/pay/save` | `{ wxQr, aliQr, wxName, aliName, amount, note }` | URL 必须落在 `/uploads/` 内；姓名≤40 字；amount≥0；说明≤200 字 | 写入 `data/payinfo.json` 持久化 | `{ok, payInfo}` |
| `POST /api/pay/info` | `{}` | — | 读取 `data/payinfo.json`（缺省返回空配置） | `{ok, payInfo}` |

配套改动：`readBody` 上限 1MB → 2.5MB（否则大图 base64 会被截断）；`MIME` 补 `.jpeg`/`.webp`；`uploads/`、`data/` 目录自动创建并加入 `.gitignore`；静态服务已能托管 `/uploads/*`。

## D. 付款人侧收款弹窗（支付闭环）

`payCollect(opt, onDone)`：读 `config.payInfo` → 未配置二维码时**直接回调**（完全兼容旧行为）；已配置则弹出 `#collectSheet`：

```
金额（money 格式化）→ 标题（如「沙龙报名 · xxx」）→ 订单说明 → 订单号/备注
[微信支付 | 支付宝] 切换 → 200×200 二维码 + 收款人 → 「我已完成支付」
```

确认后回调携带 `payMethod`，各入口再执行原落库逻辑。因此：**配置了收款码 = 扫码收款模式；未配置 = 原模拟支付模式**，无需开关切换。

# v=134 增量：「我已完成支付」按钮解锁逻辑（后端确认到账）

## 支付确认机制（个人收款码场景）

| 角色 | 动作 |
|---|---|
| 付款人 | 打开收款弹窗 → 后端自动创建**待确认订单**（5 分钟有效）→ 每 3 秒轮询状态 → 状态条提示「等待付款确认中」 |
| 收款方（后台） | 订单管理 →「扫码收款确认」台账 → 核实款项到账 → 点「✓ 确认到账」（或「作废」） |
| 付款人 | 轮询到 paid → 状态条变绿「✅ 已确认到账」→ 按钮解锁 → 点击进入后续落库流程 |

## 按钮状态机

```
禁用（灰显，点击 toast「请等待支付结果确认」）
  ├─ 轮询 status=paid    → 解锁（绿色提示「已确认到账」）→ 点击落库（防重复：submitting 锁 + 弹窗关闭即停轮询）
  ├─ 轮询 status=expired → 提示「二维码已过期或支付超时」→ [🔄 重新获取二维码]（新建订单重新计时，旧单不可再确认）
  ├─ 连续 3 次查询失败   → 提示「支付结果查询失败」→ [🔄 重新查询]
  └─ 后端完全不可达      → 兜底为直接确认模式（避免静态部署时收款流程卡死），状态条明确标注
```
